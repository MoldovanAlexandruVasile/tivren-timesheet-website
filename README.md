# Tivren website

Marketing page for Tivren Timesheet, the offline timesheet app, with a download
link for the macOS `.dmg`. React + TypeScript + Vite, hosted on Netlify.

## Run

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # → dist/
```

## Deploy

Hosted on Netlify at https://tivren.netlify.app. Pushing to `main` builds and publishes the
site (settings in `netlify.toml`). One-time setup in Netlify: import this repo,
and under Site configuration → Environment variables add `NODE_AUTH_TOKEN` (a
GitHub token with `read:packages`, marked secret, Builds scope) so npm can
install `@moldovanalexandruvasile/unity-marketing` from GitHub Packages.

## Releases (published automatically)

The Tivren source repo is private and the installers (~125 MB each) are too
big to commit, so each version ships as a **release on this repo**, published
by the app repo's release workflow when a version tag is pushed there
(`npm run release:patch` in `tivren`; see its `desktop/README.md` › Releases).
Each release holds:

- `Tivren-arm64.dmg`, `Tivren-x64.dmg` and `Tivren-Setup-x64.exe`: what the
  download buttons serve;
- `tivren-mac-<arch>.json` / `tivren-win-x64.json` (signed) with
  `Tivren-mac-<arch>.zip` / the installer: what the installed apps read to
  update themselves;
- the same under their earlier names (`Shiftify-…`, `latest-….json`), for
  installs from before the app was renamed.

Don't rename, edit or re-upload them by hand: the apps reject anything that
doesn't match the signature.

The download buttons link to `releases/latest/download/<file>`, so they always
serve the newest release without a site change. The version and size next to
them are read from the GitHub API at page load. Owner, repo and file names
live in `src/config.ts`.

## Screenshots and promo video

Everything in `public/media` (and the full-size slides in `marketing/slides`,
2880×1800 for the Mac App Store) is generated by `capture/`, from Tivren's
real web build:

```bash
cd capture
npm install && npx playwright install chromium
node serve.mjs ../../tivren/desktop/app 8091   # in another terminal
node capture.mjs    # enters demo data, saves raw screens + card positions → raw/
node slides.mjs     # marketing slides (slides.html) → marketing/ + public/media/slides
node promo.mjs      # 25 s motion promo (promo.html) → public/media/promo.mp4
```

Romanian: the same with `ro` first (`node capture.mjs ro`, `node slides.mjs ro`,
`node promo.mjs ro`). The app is captured in Romanian (`raw/ro/`), the slides
and the promo take their Romanian texts, and everything lands in
`public/media/ro/` (and `marketing/slides/ro/`) under the same names. The two
hero screenshots (`media/app/`, `media/ro/app/`) are the raw `calendar.png`
and `calendar-dark.png` at 1600 px (`sips -Z 1600 -s format jpeg`). The site
picks the folder by the page's language (`src/hooks/useMediaUrl.ts`).

`promo.mjs 3 12.5` renders stills at those seconds instead, for checking a
change to `promo.html`. The video is encoded with AVFoundation
(`encode.swift`), so it needs macOS but no ffmpeg.

## Privacy policy and Terms of use

`privacy.html` and `terms.html` show the app's own legal texts (the Mac app
version), copied from the tivren repo into `src/legal/` (English and Romanian). After changing them
in the app, run `npm run sync:legal` here and commit.

## Languages

English and Romanian, with react-i18next. Site text lives in
`src/i18n/locales/{en,ro}.json` (same keys in both). Visitors get their
browser's language (Romanian for any `ro-*`, English otherwise) until they
pick one from the RO / EN menu in the top bar; that choice is remembered.
The legal pages use the app's own `en.ts` / `ro.ts` (see above), in the Mac
or Windows version for the visitor's computer.

## Styling

Tailwind CSS v4 (`@tailwindcss/vite`). `src/index.css` holds only the theme:
the app's colours as Tailwind colours (`bg-surface`, `text-muted`,
`bg-primary`…), with their dark-mode values, plus a few base rules and two
custom utilities (`bg-hero-glow`, `scrollbar-none`). Components use utility
classes; shared looks live in small components (`components/ui/`: Container,
Section, SectionTitle, Card) and `buttonStyles()`.

## SEO

- **Address:** `VITE_SITE_URL` in `.env` is the site's public address. Canonical
  links, link previews, structured data and the sitemap are all built from it,
  so a move (for example to a custom domain) is a one-line change.
- **Head tags** (`index.html`, `privacy.html`, `terms.html`): description,
  canonical URL, Open Graph and Twitter cards with `public/og-image.jpg`
  (1200×630), and on the home page schema.org `SoftwareApplication` data.
- **Pre-rendered HTML:** `npm run build` ends with `scripts/prerender.mjs`, which
  renders each page (`src/entry-server.tsx`, in English) into the built HTML.
  Crawlers and link previews see the real content without running JavaScript;
  in the browser, React takes over the page.
- **sitemap.xml / robots.txt** are written into `dist/` by the same script.
  The site is at its domain's root, so crawlers read robots.txt and find the
  sitemap from it; submitting the sitemap in Google Search Console speeds that up.
